# Deployments

One file per network, named `<network>-<chainId>.json`, holding the contract addresses,
the deploy transaction hashes, and who is authorised to write.

These files are the input to the verification CLI (T8) and the dashboard (T9): both read
addresses from here rather than hardcoding them, so pointing either at a different network
is a matter of changing which file it loads.

## Verifying a deployment yourself

Nothing here has to be taken on trust. Every field is readable from a public node:

```bash
R=https://evmrpc-testnet.0g.ai
REG=0xCF9236a145FaE855B6894Eb7951cA9619D6613a8
MR=0x9bdeC5D5749270cf20DDa5d541770839E083CAc6

cast call $REG 'providerCount()(uint16)'                 --rpc-url $R
cast call $MR  'EPOCH_DURATION()(uint32)'                --rpc-url $R
cast call $MR  'REGISTRY()(address)'                     --rpc-url $R   # must equal $REG
cast call $MR  'epochsOf(address)(uint32[])' <prober>    --rpc-url $R
```

`REGISTRY()` returning the ProviderRegistry address is worth checking specifically: it is
immutable, so a measurement ledger can never be repointed at a different set of identities
after the fact.

## Mainnet key

The deployer becomes owner of both contracts and controls which addresses may write
measurements. On mainnet that key must be generated by its owner and never pass through a
chat transcript. The testnet key in this repo's `.env` does not qualify.
